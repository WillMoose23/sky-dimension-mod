# 1.5.12 Fabric systems

Version **1.5.12** (bugfix bump from 1.5.11). The 1.5.11 change never produced a jar. This pass started replacing Nitrogen, Cumulus, and Accessories inside `The-Aether-1.21.1-1.5.10-neoforge`. `./gradlew compileJava` still fails, so no Fabric jar was built.

Toolchain is unchanged: Minecraft 26.3, Fabric Loader 0.19.5, Fabric API 0.161.0+26.3, Loom 1.18-SNAPSHOT, Gradle 9.7.1, Mojang official names.

## What changed

In-mod replacements, adapted from the Nitrogen 1.21.1-1.1.25 sources and the Aether call sites:

- Accessories: `com.aetherteam.aether.accessory` stores gloves (1), rings (2), pendants (1), capes (1), shields (1), and misc (2) on a Fabric attachment. Equip, tick, freezing, attribute modifiers, and break-on-empty are implemented there. Call sites were pointed at `AccessoryInventory` instead of Accessories.
- Boss rooms: `com.aetherteam.aether.dungeon.BossRoomTracker` and `BossMob` track players in the room, open and close doorway blocks, save the room box, and grant kill score to players in the room.
- Block-state recipes: ingredient, property pair, serializer, and function execution live in `com.aetherteam.aether.recipe.blockstate`. The serializer builds a 26.3 `RecipeSerializer` record.
- Synced data: player, mob accessory, phoenix arrow, lightning, dropped item, and Aether time attachments are Fabric `AttachmentType`s. Sync packets use `AetherNetwork` (`PayloadTypeRegistry` plus server receivers). Client sends go through reflection so the dedicated server does not link client networking classes.
- Registries: `com.aetherteam.aether.registry.DeferredRegister` registers into vanilla `Registry`.
- Config: `com.aetherteam.aether.config.ModConfigSpec` keeps the existing config keys and defaults without NeoForge.
- `ResourceLocation` was renamed to `Identifier`. Single-argument NBT reads were switched to `get*Or`. Entity `addAdditionalSaveData` / `readAdditionalSaveData` signatures were pointed at `ValueOutput` / `ValueInput`.
- JEI, REI, and Jade sources are excluded from compilation. Datagen generators and providers are excluded. No JEI or REI artifact is on the classpath.

## Follow-up port work

Minecraft classes that moved in 26.3 were remapped (slimes, pigs, arrows, boats, armor materials, criteria, game rules, density functions, surface rules to material rules). `MobSpawnType` is `EntitySpawnReason`. Item `use` results return `InteractionResult` instead of `InteractionResultHolder`.

Tools extend `Item` and apply `ToolMaterial` through `Item.Properties` (`sword`, `pickaxe`, `axe`, `shovel`, `hoe`). Armor pieces use `humanoidArmor` with `ArmorMaterial` and `ArmorType`. Spawn eggs use `Item.Properties.spawnEgg`. Registries bind immediately so holders are available during static init.

Patreon perk checks use a local `User` / `UserData` (`com.aetherteam.aether.perk.user`) instead of Nitrogen. The local user is a Human tier, so pledge-gated moa skins and halos stay locked unless that user is replaced later. Accessory render registration goes through `AccessoryRenderers`.

## Entrypoint pass

`Aether` implements `ModInitializer`. `AetherClient` implements `ClientModInitializer` and registers client packet receivers. Packets go through `AetherNetwork`. Builtin packs register with `ResourceManagerHelper.registerBuiltinResourcePack`. Player login, dimension change, block use, entity use, attacks, block breaks, damage, sleep, and level ticks go through Fabric events in `AetherFabricEvents`. Entity and block-entity renderers, model layers, particles, key mappings, menu screens, and HUD overlays register through Fabric client APIs. NeoForge listener classes were replaced with empty classes so those files no longer import NeoForge. Accessory spawn-with-gear is a mixin on `Mob.finalizeSpawn`. The NeoForge `ModelBuilder` mixin was removed.

Screens use `leftPos` / `topPos` where `getGuiLeft()` / `getGuiTop()` used to be. `ResourceKey.location()` is `identifier()`. Build-height reads use `getMinY()` / `getMaxY()`. AABB sizes use `getXsize()` / `getYsize()` / `getZsize()`. Entity `getServer()` calls go through `level().getServer()`.

Shelf, aercloud, lake, and crystal-island features implement the 26.3 `Feature` interface (`codec()` plus `place(WorldGenLevel, ChunkGenerator, RandomSource, BlockPos)`) and register their codecs on `BuiltInRegistries.FEATURE_TYPE`. Feature configuration records no longer implement the removed `FeatureConfiguration` type.

Cumulus is gone from the title screens. The Aether title screen still replaces the splash and adds the server button. The menu-list offset and NeoForge branding lines are not applied. `AetherMenuUtil` treats the Aether menu as the active menu.

## Symbol pass

`./gradlew compileJava --rerun-tasks` went from **4,237** errors to **2,285**. Three compiles in a row then dropped by fewer than 100 (98, then 45, then 16). No jar was produced. `~/Library/Application Support/minecraft/mods` was not changed.

What this pass changed:

- Entity tag checks use `getType().builtInRegistryHolder().is(tag)`.
- `DimensionTransition` is `TeleportTransition`. Mob griefing reads `ServerLevel.getGameRules()`.
- `AccessoriesCapability` call sites use `AccessoryInventory`. The accessories screen is a plain `AbstractContainerScreen`.
- Placement modifiers and loot functions register `MapCodec`s and implement `codec()`.
- Feature and placed-feature registries keep `ResourceKey<Feature>` / `ResourceKey<PlacedFeature>` keys. Java bootstrap that built `ConfiguredFeature`s is empty because that type is gone; runtime worldgen still depends on datapack JSON that is not in the mod jar.
- Noise settings build a 26.3 `NoiseRouter` and `NormalNoise`. Density functions use `net.minecraft.world.level.levelgen.densityfunction`.
- Tree placers take `TreeFeature` and `WorldGenLevel`.
- Entity type builders take `ResourceKey`s. Flower pots use `FlowerPotBlock(Block, Properties)`. Spawn entries use `addSpawn(type, category, weight, IntProvider)`.
- `FlyingMob` entities extend `Mob`. Particles extend `SingleQuadParticle`. Cow, pig, and slime models are no longer generic.
- Sword and hoe leftovers use `Item.Properties.sword` / `hoe`. Global loot modifiers no longer implement the NeoForge loot type.
- Invalid `@Override` annotations were removed. Mob renderers use `LivingEntityRenderState`. `MultiBufferSource` render methods were removed from the classes that still called that type.

## Cluster pass

`./gradlew compileJava --rerun-tasks --offline` went from **2,285** errors to **1,417**. No jar was produced. `~/Library/Application Support/minecraft/mods` has no Aether jar, so nothing was copied.

What this pass changed:

- Cooking and ban serializers no longer implement `RecipeSerializer`. They expose `toVanilla()` as `new RecipeSerializer<>(codec, streamCodec)`. Recipe types are anonymous `RecipeType`s registered under `aether`.
- `Level.recipeAccess()` replaces `getRecipeManager()`. Enchantment lookups use `registryAccess().lookupOrThrow(Registries.ENCHANTMENT).getOrThrow`. Item enchantment checks use `EnchantmentHelper`.
- Screen geometry uses `imageWidth`, `imageHeight`, `leftPos`, and `topPos`. Those fields are widened in `aether.accesswidener`. `render` is `extractRenderState`. Container backgrounds are `extractBackground`. The lore book passes its size to the `AbstractContainerScreen` constructor. The current screen is `Minecraft.gui.screen()`. HUD visibility is `Hud.isHidden()`.
- `BlockPos` centers used by named position variables go through `Vec3.atCenterOf`. Surface blocks use `RandomState.surfaceSystem().topMaterial` instead of `CarvingContext`. Biome builders take `HolderGetter<WorldCarver>` from `Registries.CARVER`.
- Structure processors implement the `StructureProcessor` interface and register `MapCodec`s. Boss-room entity NBT is not applied during placement, because 26.3 processors only see blocks.
- Block entity types are `new BlockEntityType<>(factory, Set.of(blocks))`. Cauldron interactions register on `CauldronInteractions` dispatchers. Leather-glove dye washing is not registered; the vanilla dye interaction is private.
- Packets use `CustomPacketPayload.Type`. `displayClientMessage` is `sendOverlayMessage`. Fall-distance resets use `resetFallDistance()`. Boats take an item supplier. `Saddleable` is gone; saddled checks use `Mob.isSaddled()`.
- The dimension-type mixin was removed. `timeOfDay`, `moonPhase`, and `effectsLocation` are gone. Aether checks use `Level.dimension() == AetherDimensions.AETHER_LEVEL`. Aether day length is no longer injected into `DimensionType`.
- Crystal and cloud-minion models extend `EntityModel<EntityRenderState>`. Config loot conditions register a `MapCodec`. Translator and celebrity moa-skin groups are not checked.
- A later file pass took the compile from **1,787** to **1,417**. HUD hearts use `Hud.HeartType`. Moa UUIDs are strings. Sentry goals follow `AbstractCubeMob`. Altar, freezer, and incubator fuels are in-code maps. Farmland extends `FarmlandBlock`. Quicksoil-magma fluid interaction is not registered. Berry-bush model wrapping is an empty class. Aether day time uses `ServerClockManager.setTotalTicks` on the overworld clock.

## Limits

Largest failing files (unique error counts): `ValkyrieQueen.java` (17), `IncubatorBlockEntity.java` (16), `AetherItems.java` (16), `FloatingBlockEntity.java` (15), `AbilityHooks.java` (15), `SunAltarWhitelistCommand.java` (14), `GlovesLootModifier.java` (14), `AetherPlayerAttachment.java` (14). NeoForge event parents and loot modifiers are still in the compile. These files were not fully rewritten in this pass.

Gameplay still not preserved: player dart, halo, and wing layers are not attached; berry-bush model wrapping is not applied; grass and item tints are not registered; recipe-book categories are not registered; the Aether sky is not drawn (`DimensionSpecialEffects` is gone); gummy-swet and life-shard tooltip overrides are not applied; the Valkyrie lance and hoe no longer add extra interaction range and the lance does not block sweep; global loot modifiers (double drops, gloves, pig drops, enchanted grass, seed removal) are not applied; damage-amount reduction and zanite break-speed are not applied; worldgen Java bootstrap does not run, and the generated 1.21 worldgen JSON is not packaged. Pledge perks stay on the Human tier. Spawn egg colors are not stored. Config values stay at their defaults.

In-game behavior was not tested.
